# M3 — Adaptive layouts and Liquid Glass (weeks 10–12)

Goal: every screen correct at every width, so the foldable, split-screen and iPad work without device-specific code.

## Tasks

- [x] **Compact layout** (folded phone, narrow split-screen slots). The Watch screen stacks the video over scrolling details; the feed is single-column.
- [x] **Medium layout** (unfolded ~4:3 phone, iPad portrait): the video with a **band below** holding Details / Comments / Chapters tabs. Comments are paginated and load on first view; tapping a chapter seeks.
- [x] **Expanded layout** (full iPad): a sidebar via `TabView` with `.sidebarAdaptable`, plus a **Channels** section listing subscriptions. Wide Watch windows get a **side panel**.
  - **Deviation from the plan:** the plan names `NavigationSplitView`. The sidebar-adaptable `TabView` is the system Liquid Glass control for exactly this, and it becomes a tab bar again in compact width. Prefer system components (CLAUDE.md).
- [x] **Per-scene routers with typed routes:**
  - `SceneRouter`, one per window, holds `Route.channel(…)` and a path per stack, so feature screens never own navigation.
  - iPad windows browse independently and share the one `PlaybackSession`.
- [x] **Glass player controls** show on tap and fade during playback (M0's `PlayerControlCluster` in a `GlassEffectContainer`, with `glassEffectID` morphing). Controls stay visible while VoiceOver runs.
- [x] **Haptics:** play/pause, subscribe, and a successful pull-to-refresh.
- [x] **Dynamic Type and VoiceOver:**
  - Cells combine into one element with the button trait, headers are marked, and hints are on channel links and chapters.
  - `AdaptiveLayoutUITests` runs Xcode's accessibility audit on the feed, settings and search at the largest accessibility text size.
- [x] **Resize-during-playback UI test.** XCUITest can't resize windows, so `testRotatingDuringPlaybackNeverStalls` rotates the device six times during real playback. It fails if the surface disappears, the state leaves `playing`, or the position ever stops advancing.

**Layout rule:** `WatchLayout.choose(width:height:horizontal:)` picks by available size and size class, never by device model. It's unit-tested with folded-phone, unfolded, iPad and slim-window sizes.

**Done when:** every screen is verified at all widths, and resizing or folding never interrupts playback.

## Verified (simulator, owner's Piped instance)

- **iPhone 18 Pro:**
  - Compact Watch layout, feed, search and channel.
  - Six rotations during playback, never stalling (`testRotatingDuringPlaybackNeverStalls`).
  - Accessibility audit clean at AX-XXXL: feed, settings, search.
- **iPad Pro 13" portrait** (`IPadLayoutUITests`):
  - Sidebar-adaptable tabs.
  - Three-column feed grid.
  - Watch band with Comments loading real comments.
  - Rotating to landscape keeps playing.
  - The landscape screenshot was captured mid-rotation, so the **side-panel layout is verified by `WatchLayoutTests` and by playback continuity, not visually**. Owner to eyeball it.

## Found and fixed by these checks

- **Watch sheet compact on iPad:** a sheet on iPad is a compact form sheet, so the Watch screen never reached the band or side panel. Watch now presents full screen everywhere; the zoom transition keeps swipe-to-dismiss, and there's an explicit close button.
- **iPad feed:** it was one giant column. It's now an adaptive grid, with columns of at least 320 pt.
- **Clipped text:** fixed line limits clipped titles at accessibility sizes; cells now grow instead.
- **Pluralisation:** "1 likes" / "1 replies" now use automatic grammar agreement.
