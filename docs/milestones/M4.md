# M4 — System integration (weeks 13–15)

Goal: connect the player to the rest of the system, laying the groundwork for CarPlay.

## Tasks

- [x] **`AVPlayerEngine`:**
  - Audio-only plays the AAC (m4a) stream directly.
  - Adaptive video plays through on-device HLS.
  - HLS and progressive sources play as-is.
  - Stats come from AVPlayer's access log.
  - HTTP 401/403/410 map to `.streamExpired`, so the shared recovery refetches.
- [x] **Audio mode toggle:** switches engines and keeps the position (mpv ⇄ AVPlayer, re-planned from the current page). The UI test checks the position never goes backwards or jumps.
- [x] **Background audio and the audio session:**
  - `.playback` with the long-form video policy, and `UIBackgroundModes: audio`.
  - In the background without PiP, video decoding stops and audio continues (`setVideoEnabled`).
- [x] **Now Playing info and remote commands** (`NowPlayingController`):
  - Title, artist, artwork through the image pipeline, duration and elapsed time.
  - Remote play, pause, toggle, ±15 s and scrubbing.
- [x] **Picture-in-Picture in production:** the M0 handoff wired into the Watch screen for mpv video (H.264, or AV1 on hardware-AV1 devices). The position returns to mpv afterwards. *Automatic* PiP on backgrounding isn't possible while mpv is the inline player (see notes).
- [x] **AirPlay:**
  - The system route picker is in the Watch screen's action bar.
  - Picking an AirPlay route moves video to AVPlayer (`allowsExternalPlayback`) at the same position; leaving it moves back to mpv.
- [x] **Google Cast to the default media receiver** (ADR 0003), without Google's SDK:
  - Our own Cast v2 sender.
  - Discovery in the app finds the owner's "Chromecast" and "Sony BRAVIA".
  - A live read-only exchange (`GET_STATUS` → `RECEIVER_STATUS`) succeeds.
  - Casting sends the instance's HLS or DASH URL, and a "Playing on …" overlay carries the controls.
- [x] **SponsorBlock with auto-skip:**
  - Lookups by hash prefix; categories sponsor, self-promotion and interaction reminders.
  - Each segment is skipped once per load (seeking back into one plays it).
  - A "Skipped sponsor" notice appears, announced to VoiceOver.
  - On by default.
- [x] **DeArrow:**
  - Community titles via hash-prefix lookups, opt-in.
  - Community thumbnails are a separate opt-in, because that service is asked for the specific video.
  - Stored in a `branding` table, looked up after each refresh, with misses remembered for a day.

**Done when:** switching from video to audio and back keeps the position, and casting to your Google TV works.

- **Audio mode:** verified (`SystemIntegrationUITests`).
- **Casting:** discovery and protocol are verified live. **An actual `LOAD` to the TV awaits the owner's go-ahead**, since it plays on a TV in their home.

## Found and fixed

**Crash on first playback with artwork.** The `MPMediaItemArtwork` handler was written inside `@MainActor` code, so it inherited main-actor isolation. MediaPlayer calls it on a background queue, and Swift 6 traps there.

- **Fix:** the handler is built in a `nonisolated` helper.
- **Regression test:** calls the handler from a background queue.
- **Same treatment:** KVO and remote-command handlers.
- **Rule recorded:** in CLAUDE.md.

## Notes

- **Automatic PiP.** iOS starts PiP automatically only from an inline `AVPlayerLayer`. With mpv inline, PiP is a button (handoff). For automatic PiP, AVPlayer would have to play inline whenever it can deliver the selected format: H.264 ≤1080p, or AV1 on hardware-AV1 devices, keeping mpv for VP9 and higher resolutions. That changes a CLAUDE.md non-negotiable, so it's proposed to the owner rather than done.
- **Casting** needs the instance to offer HLS or DASH. Piped VOD `hls`, Invidious `dashUrl` and YT Zero tickets all do.
