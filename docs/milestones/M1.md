# M1 — Sources and data (weeks 3–5)

Goal: the source layer and the local-first data model every screen renders from. Decisions: `docs/adr/0002-sources-subscriptions-sync.md`.

## Tasks

- [x] `VideoSource` protocol with declared capabilities (search, trending, channel, comments, streams, subscriptions, playlists). `SubscriptionAccount` covers sources that own the user's subscriptions and watch state.
- [x] Piped adapter (`Core/Adapters/Piped`). Error classification from Java exception names; WebVTT captions; LBRY and muxed entries skipped.
- [x] Invidious adapter (`Core/Adapters/Invidious`):
  - Codecs read from the MIME type (AV1 itags are missing from its table).
  - Dubbed and DRC tracks identified from `xtags`.
  - Per-channel Atom feeds, since there's no batched feed.
  - Overlapping playlist pages de-duplicated.
- [x] YT Zero adapter, tested against **2026.09.9** (the owner's instance):
  - Device-code sign-in.
  - Account feed and subscriptions.
  - Playback tickets.
  - Thumbnails through the instance's image cache.
  - Progress and watched state written back.
- [x] Capability routing (`InstanceRouter`):
  - Ranks instances by measured latency.
  - Fails over only on errors that are retryable elsewhere.
  - Cools an instance down per capability: 15 min when YouTube blocks it, exponential backoff after repeated failures.
  - When every instance is cooling down, tries them anyway.
- [x] Instance health checks (`healthCheck()` per adapter, `InstanceRouter.checkHealth()`); passive health from real traffic.
- [x] Onboarding: paste a URL, the app detects Piped, Invidious or YT Zero (`InstanceDetector`), YT Zero pairs by code or QR, then the instance is saved. Subscription import covers Google Takeout CSV, NewPipe, FreeTube and Piped JSON, and OPML.
- [x] GRDB schema `v1`: instances, subscriptions, videos, watch state, refresh log, manifest cache. The synced tables carry `modifiedAt`, a tombstone and CloudKit system fields.
- [x] Subscription source of truth decided (ADR 0002): YT Zero when linked, otherwise local and synced through the CloudKit private database. Sync ships in M7.
- [x] Stale-while-revalidate:
  - Observation: stores expose plain async streams over `ValueObservation`.
  - `FeedRefresher`: local or account mode, and concurrent refreshes coalesce.
  - Triggers: launch, foreground, pull-to-refresh and instance changes, plus backfill for channels with no cached videos yet.
- [x] Contract tests against the owner's three instances. `scripts/contract-tests.sh` reads `.env.local`, which is never committed: **14/14 pass**. Fixture-based decoding tests run on every CI build.

**Done when:** contract tests pass against all three instances, and the feed renders from cache on the first frame after launch.

## Notes

- **Piped feed window:** `/feed/unauthenticated` only carries the last 30 days, and a channel new to the instance returns nothing until the instance has fetched it. Hence the backfill through `channel(_:)` after import or instance changes.
- **YT Zero thumbnails** need the Bearer token (`/api/img`). `AsyncImage` can't send it, so they load once the M2 image pipeline lands.
- **YT Zero playback tickets** last 15 minutes. Today an expired ticket surfaces as `.streamExpired`, and the session refetches and resumes. Renewing tickets in the background is an M2 refinement.
