# M0 — Foundations and risk spikes (weeks 1–2)

Goal: prove the risks that could force a redesign before any feature work starts.
Do the tasks in order. Each spike ends with a short written result in `docs/spikes/<name>.md`:
what was tried, what worked, measurements, and a recommendation.

## 0. Owner action (not for Claude Code)

- [ ] Request the CarPlay audio entitlement from Apple. Approval is separate from App Review and can take a while.

## 1. Project skeleton

- [x] Xcode project with an iOS app target in `App/iOS` (iPhone + iPad, iOS 26 minimum).
- [x] Local Swift packages under `Packages/`: `Core`, `Library`, `Playback`, `DesignSystem`, `Features`.
      `Core` and `Playback` already contain the contracts (revised in `docs/adr/0001-contract-revision.md`) with tests; keep them compiling and green.
- [x] Swift 6 language mode everywhere; main-actor default isolation for the app and feature targets.
- [x] `CADisableMinimumFrameDurationOnPhone = YES` in Info.plist.
- [x] Add GRDB to `Library` (empty schema for now) and record its license in `docs/licenses.md`.

**Accept when:** the app builds and launches in the iOS simulator showing a placeholder screen, and package dependency rules from CLAUDE.md are enforced.

## 2. CI and performance harness

- [ ] CI workflow (GitHub Actions on a macOS runner, or Xcode Cloud) that builds and runs unit tests.
- [ ] `os_signpost` helpers with the gate names from CLAUDE.md, including `playback.manifest`.
- [ ] XCTest performance target with: launch metric, a scroll test over a placeholder list of 1,000 cells measuring hitch ratio, and a signpost-interval test.
- [ ] A placeholder 120 Hz animation screen to verify ProMotion on device.

**Accept when:** CI is green and prints the metrics. Owner verifies 120 Hz on a ProMotion iPhone.

## 3. Design system seed

- [ ] Color, spacing, radius and type tokens in `DesignSystem`.
- [ ] One glass control cluster built with `GlassEffectContainer`, plus a preview.

**Accept when:** previews render in light and dark mode.

## 4. Spike: LGPL mpv build

- [ ] Evaluate MPVKit (check whether it ships an LGPL-only product) versus building libmpv and FFmpeg yourself with GPL and nonfree components disabled.
- [ ] Produce an XCFramework (or SPM binary target) for iOS device + simulator, and tvOS device + simulator.
- [ ] Document configure flags, the resulting license, and how to rebuild in `docs/spikes/mpv-build.md`.

**Accept when:** the app links libmpv for iOS device and simulator, and the build is reproducible from the documented steps. No GPL components.

## 5. Spike: mpv rendering and hardware decode

- [ ] Minimal `MPVEngine` conforming to `PlaybackEngine`, rendering into its own layer inside a `RenderSurfaceHost`.
- [ ] Prefer a Metal-backed path (for example gpu-next through MoltenVK into a `CAMetalLayer`); avoid the deprecated OpenGL ES path unless nothing else works, and document why.
- [ ] `hwdec=videotoolbox`; emit `PlaybackEvent.decoder` with the codec and whether hardware decode is active.
- [ ] Emit `PlaybackEvent.stats` about once a second (dropped frames, buffer ahead, download throughput) from mpv's properties.
- [ ] Debug screen: paste stream URLs (separate video and audio), play, and show decoder info, dropped frames and resolution.
- [ ] Wire `PlaybackSession` so the debug screen can be dismissed and reopened while playback continues.

**Accept when (owner verifies on an iPhone with A17 Pro or later):** an AV1 2160p stream plays with hardware decode reported, without sustained dropped frames; a VP9 1440p stream plays in software decode; reopening the screen does not interrupt playback.

## 6. Spike: on-device HLS for AVPlayer

Hypothesis: the MP4 adaptive streams are fragmented MP4 with a segment index (sidx). From `initRange`/`indexRange` the app can write an HLS playlist locally (`EXT-X-MAP` plus `EXT-X-BYTERANGE` segments, a master playlist with an audio group) and hand it to AVPlayer, with no server-side remuxing. If it holds, it unlocks AirPlay video and native PiP, and gives a fallback if spike 5 fails, for H.264 and (on AV1-hardware devices) AV1. VP9 is webm and still needs mpv.

- [ ] Fetch the index range for an H.264 and an AV1 MP4 stream; parse sidx into segment byte ranges.
- [ ] Serve the generated playlists to AVPlayer (`AVAssetResourceLoaderDelegate` with a custom scheme, or a loopback server); segment URLs point at the proxied stream.
- [ ] Measure tap-to-first-frame, seek latency and memory against spike 5's mpv path.
- [ ] Try AirPlay to an Apple TV, and PiP.

**Accept when:** `docs/spikes/local-hls.md` reports whether AVPlayer plays the synthesised playlist (H.264 in the simulator; AV1, AirPlay and PiP verified by the owner on device), with measurements and a go/no-go.

## 7. Spike: Picture-in-Picture with mpv

- [ ] Investigate PiP via `AVPictureInPictureController` with an `AVSampleBufferDisplayLayer` content source, fed with frames from mpv.
- [ ] If libmpv's render API cannot deliver frames for this path efficiently, document the blocker and compare fallbacks: hand off to AVPlayer with spike 6's on-device HLS (preferred: no server), or a gateway that remuxes DASH to HLS.

**Accept when:** PiP works on device with the mpv path, or `docs/spikes/pip.md` recommends a fallback with measured trade-offs. Owner verifies on device.

## Report back at the end of M0

- Results of each spike and the recommendation.
- Measured numbers from the performance harness.
- Any change to the contracts, recorded as an ADR in `docs/adr/`.
- The list of manual on-device checks the owner still needs to run.
